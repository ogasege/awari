WHAT IT IS: Awari (Yoruba for discovery) is my entry for the Kiroween 2026 hackathon on Devpost, Resurrection category. It brings back the 1990s CD-ROM encyclopedia as a free, offline-first web app for curious students. HARD RULES (breaking one can disqualify the entry): (1) the repo root must contain a .kiro folder with steering, specs and hooks, never gitignored; (2) never use the name Encarta or Microsoft's logo, layout or artwork anywhere, Awari is an original design; (3) public GitHub repo with an MIT LICENSE, and all content openly licensed and credited; (4) the app must stay free and online until 29 January 2027; (5) all code is new work, copy nothing from other projects; (6) deadline is Friday 4 December 2026 at 2:00 pm Pacific, feature freeze Friday 27 November, target submission Wednesday 2 December. SETUP: (1) create the project folder awari inside my workplace folder in my home directory and run git init; (2) if a folder or zip named awari-kit exists in my Downloads folder, copy its design folder and KICKOFF.md into the project, and if it is not there yet carry on, I will add it later; (3) write steering files in .kiro/steering: product.md, tech.md, structure.md, design.md (the DESIGN section below, word for word) and hackathon-rules.md (the hard rules); (4) for each feature below create a spec folder in .kiro/specs with requirements.md in EARS format with numbered acceptance criteria, design.md and tasks.md, derive correctness properties from the requirements and cover them with property-based tests; (5) create hooks in .kiro/hooks that run lint and unit tests when a source file is saved, check that every bundled photo and data file has a licence entry in CREDITS.md, and update docs/kiro-log.md when a spec task is completed; (6) keep docs/kiro-log.md as a dated record of which spec, hook or steering file drove each piece of work, because that is the evidence for the judges; (7) commit after every completed task with the spec and task number in the message. BUILD, IN THIS ORDER: (1) App shell and design system in React, TypeScript and Vite: shared header, routes, tokens and the hand-made components from the DESIGN section; done when Home matches design/home.png at 1440 px wide and reflows to one column on a phone. (2) Content packs: a build script that turns open data into static JSON packs for Countries (Simple English Wikipedia articles plus Wikidata facts), Physics (starting with electricity) and Dictionary (Open English WordNet); done when the packs build from one command and every record carries its source and licence. (3) Articles and dictionary: a photo-led article page where tapping any word shows its meaning in a side card; done when the Nigeria article renders from the pack and the word delta resolves offline. (4) Atlas: a globe the student can spin, built from Natural Earth shapes, where countries they open are marked as discovered; done when selecting a country shows its facts and links to its article and quiz. (5) Quizzes with a hint ladder: five questions per article and three hints per question (a nudge, then where to look, then two wrong answers removed); after a correct answer show the sentence from the article that proves it; right and wrong states always carry words, never colour alone; done when the Nigeria quiz works offline. (6) The Castle: a room-by-room trivia game using the same question bank, where each correct answer lights the next room; done when a wing of twelve rooms can be completed. (7) Timeline and On this day: dated events from Wikidata, filterable by subject, with three events for today's date on Home. (8) Stamp book: each discovered country becomes a postage stamp on Home, with a count out of 54 for Africa. (9) Offline: service worker plus IndexedDB; done when, after one visit, every pack feature works in airplane mode. (10) Quiz service: one AWS Lambda calling Amazon Bedrock to generate questions and hints for articles outside the packs, validating every generated question against the article text before returning it; the app must work without this service. (11) Infrastructure: Terraform for S3, CloudFront and the Lambda; static site, no servers. (12) Submission pack: README.md (what it is, how Kiro was used, how to run), CREDITS.md, a 2 minute 55 second video script in docs/video-script.md and a Devpost write-up draft in docs/devpost.md. If time runs short, cut in this order: timeline, quiz service, Physics pack, dictionary. Never cut offline, quizzes with hints, or the atlas. CONTENT AND LICENCES: Wikipedia and Simple English Wikipedia text is CC BY-SA 4.0 and must be credited on every article; Wikidata is CC0; Natural Earth is public domain; Open English WordNet is CC BY 4.0; photos come from Wikimedia Commons only, with author and licence in CREDITS.md; every fact in a handwritten note must be true and checked against the article it points to. DESIGN: You are the art director and lead illustrator for Awari, with a background in children's editorial design and cut-paper collage. Every screen must look assembled by a person at a desk, never laid out by a grid. Feel: a scrapbook kept by an excited explorer; inviting, playful, a bit messy on purpose, always readable. Colours (Lagoon): teal #00606E for dark board areas; coral #FF8662 for the photo table; yellow #FFD23F for accents, buttons and chalk highlights; navy #0B1B4D; teal ink #007A8C on paper; tomato #E8452C in small amounts; white paper #FFFFFF; text ink #101828. Long reading text is always dark on white. Type: Bricolage Grotesque 800 for headings, Figtree for body text, Covered By Your Grace for anything handwritten. Design rules: (1) lead with real photographs shown as physical prints, with white borders, 2 to 5 degree rotations, overlaps, tape, pins and handwritten captions; (2) headlines sit on hand-cut paper strips at slightly different angles with hard offset shadows; (3) add handwritten margin notes that ask a question or share one true fact, with hand-drawn arrows pointing at the thing; (4) draw doodles as wobbly SVG strokes (stars, arrows, circles, small sketches), never clean icons; (5) divide sections with torn-paper edges and let at least one object cross each boundary; (6) show progress as drawn objects: stamps collected, doors lit, hints left; (7) keep navigation, body text, buttons and form fields straight and calm, and hide everything decorative from screen readers and from phones where it would crowd the content; (8) hover straightens and lifts an object, with no other animation, and reduced-motion settings are respected; (9) laptop first, reflowing to one column on a phone. design/home.html and design/home.png from the kit are the reference for Home; design the other five screens (Atlas, Article, Quiz, Castle, Timeline) in the same style before building them. Before finishing any screen ask: could a template have made this? If yes, add one human touch that carries meaning and remove one that does not. QUALITY BAR: unit and property-based tests pass before a task is marked done; everything is keyboard reachable with visible focus and WCAG AA contrast; first load is under 300 KB of JavaScript before packs, and packs load on demand; no secrets in the repo.
